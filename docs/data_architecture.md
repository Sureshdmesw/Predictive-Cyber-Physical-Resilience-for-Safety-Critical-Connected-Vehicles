# Data Architecture

# Predictive Cyber-Physical Resilience for Safety-Critical Connected Vehicles

## 1. Purpose

The data architecture defines how historical NHTSA safety data, vehicle telemetry, Edge-IoT telemetry, cybersecurity events, connectivity measurements, forensic evidence and fleet intelligence are represented and connected.

The architecture maintains a strict distinction between historical safety data and cybersecurity telemetry.

---

## 2. Primary Data Domains

### Domain A — NHTSA Safety Intelligence

Sources:

- CISS
- CRSS
- FARS
- SCI
- ADAS
- NiTS

Purpose:

- Historical crash context
- Occupant context
- Vehicle context
- Safety-system context
- Injury/outcome context
- ADAS-related context
- Safety-risk modeling

These datasets are not treated as live cybersecurity telemetry.

---

### Domain B — Vehicle Cyber Telemetry

Sources:

- CAN
- CAN-FD where applicable
- ECU communications
- Diagnostic activity
- Gateway events
- Authentication events
- Command activity

Purpose:

- Behavioral modeling
- ECU communication modeling
- Cyber anomaly detection
- Attack classification

---

### Domain C — Physical and Safety Telemetry

Sources:

- Occupant position
- Seat position
- Restraint state
- Vehicle speed
- Acceleration
- IMU
- Vehicle dynamics
- ADAS state
- Crash-state indicators

Purpose:

- Physical-state estimation
- Sensor consistency analysis
- Cyber-physical correlation
- Safety consequence estimation

---

### Domain D — Connectivity Telemetry

Sources:

- RSSI
- Latency
- Jitter
- Packet loss
- Retransmissions
- Connection resets
- Throughput
- Route changes
- Gateway health
- Interface errors
- Primary-channel state
- Auxiliary-channel state

Purpose:

- Connectivity health monitoring
- Degradation detection
- Connectivity-loss prediction
- Malicious suppression analysis
- Resilience-state transitions

---

### Domain E — Security Intelligence

Generated by the detection system:

- Anomaly scores
- Behavioral deviations
- ECU graph deviations
- Sensor inconsistencies
- Cyber-physical correlations
- Attack hypotheses
- Threat confidence
- Safety-risk estimates
- Connectivity-risk estimates

---

### Domain F — AI Reasoning

Generated by the AI reasoning layer:

- Incident explanation
- Attack hypothesis
- Evidence references
- Confidence
- Potential impact
- Investigation recommendations
- Approved response recommendation

AI output must remain distinguishable from deterministic system decisions.

---

### Domain G — Response and Forensics

Generated by deterministic policy and forensic systems:

- Response policy
- Response action
- ECU isolation state
- Command rejection
- Safety-state transition
- Auxiliary-channel activation
- Evidence hash
- Event sequence
- Model version
- Policy version
- Timestamp

## 3. NHTSA Integration Model

The NHTSA datasets will be treated as a Safety Knowledge Layer.

Conceptually:

NHTSA historical data
        |
        v
Data ingestion
        |
        v
Data quality validation
        |
        v
Dataset-specific normalization
        |
        v
Common safety schema
        |
        v
Safety feature engineering
        |
        v
Safety Knowledge Layer
        |
        v
Cyber-Physical Risk Fusion

The system shall not assume that every NHTSA dataset contains the same variables or supports the same analytical task.

Dataset-specific fields and limitations shall be documented before harmonization.

---

## 4. Common Safety Entity Model

The normalized representation should investigate relationships among:

### Crash

- Crash identifier
- Time
- Location/context
- Crash configuration
- Impact characteristics
- Environmental context

### Vehicle

- Vehicle identifier
- Vehicle characteristics
- Vehicle configuration
- Safety-system information
- ADAS-related information where available

### Occupant

- Occupant identifier
- Seating position
- Restraint status
- Occupant characteristics where available
- Injury outcome

### Safety System

- Restraint system
- Airbag-related information
- Seatbelt information
- ADAS information
- Other relevant safety systems

### Outcome

- Injury
- Injury severity
- Fatality where applicable
- Safety consequence

The exact fields will be determined from the actual datasets rather than assumed in advance.

- event_type

- cyber_features

## 9. Training / Validation Separation

NHTSA historical data shall not be mixed indiscriminately with simulated cybersecurity attack data.

The project shall maintain separate provenance for:

- Historical safety observations
- Simulated vehicle telemetry
- Simulated attack telemetry
- Derived features
- Model outputs
- AI-generated reasoning
- Deterministic response decisions

---

## 10. Data Provenance

Every derived dataset should retain:

- Source dataset
- Source version/year
- Transformation version
- Feature-generation version
- Timestamp
- Processing pipeline version

This is required for reproducibility.

## 12. Core Principle

Historical safety intelligence explains potential consequences.

Vehicle telemetry describes current state.

Cybersecurity telemetry describes potential malicious behavior.

Connectivity telemetry describes communication resilience.

AI provides reasoning.

Deterministic policies control safety-critical actions.

Forensics preserve evidence.

Fleet intelligence improves future detection.
